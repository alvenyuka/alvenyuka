## How I build and check a model

What sits behind the results above, with the file that shows each step.

- **Validation that matches how the model will be used, and what it is a model of.** The fraud and Kiva models learn from earlier records and are tested on later ones (fraud PR-AUC 0.9971 across four later windows; PaySim is a simulator, so the model card treats real-world performance as unproven). The credit data has no dates, so its holdout is a random 20%, a limit its validation report flags. The validation report also states plainly that the credit target is Home Credit's own "payment difficulties" flag, not the 90-days-past-due default under Basel or IFRS 9's rebuttable presumption, so the model is a probability of that flag, not a regulatory PD. [validate.py](https://github.com/alvenyuka/Fraud-Detection-System/blob/main/src/validate.py) · [VALIDATION_REPORT.md](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/docs/VALIDATION_REPORT.md)
- **Leakage guards with tests.** Kiva drops the four fields that exist only once a loan is funded, and a test fails if one returns; the fraud tests fail if tuning or the threshold choice touches the rows it is scored on. [Kiva test_features.py](https://github.com/alvenyuka/Kiva-Loans-Microfinance-Analytics/blob/main/tests/test_features.py) · [test_pipeline_guards.py](https://github.com/alvenyuka/Fraud-Detection-System/blob/main/tests/test_pipeline_guards.py)
- **A simpler model to beat.** The scorecard against LightGBM (AUC 0.754 against 0.781, the price of a score a credit officer can read), Kiva's model against a constant baseline, and the Kenya aid model against a rule of thumb, which it did not beat. [challengers.py](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/src/challengers.py) · [rule_of_thumb.py](https://github.com/alvenyuka/kenya-aid-flows/blob/main/baseline/rule_of_thumb.py)
- **From a score to a business decision.** An 80% approval cut-off that cuts holdout credit losses by 47%, a fraud threshold set from the cost of a missed fraud against a false alarm, a Kiva review list where the riskiest 10% of loans hold 76% of the unfunded dollars, and IFRS 9 expected credit loss under three scenarios on a synthetic SACCO book. [business_impact.py](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/src/business_impact.py) · [stress_test_engine.py](https://github.com/alvenyuka/SACCO-Stress-Test/blob/main/stress_test_engine.py)
- **Decisions that can be explained.** Up to three reason codes for each declined applicant, from the points lost against the best bin; SHAP for the fraud and Kiva models; sex and marital status kept out of the scorecard, with tests that fail if they return. [scorecard.py](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/src/scorecard.py) · [test_fair_lending.py](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/tests/test_fair_lending.py) · [explain.py](https://github.com/alvenyuka/Fraud-Detection-System/blob/main/src/explain.py)
- **Methods checked from first principles.** Logistic regression written from scratch and matched to scikit-learn; AUC, KS, Gini and PSI coded by hand and tested against scikit-learn and SciPy, which caught a KS error on tied scores. [from_scratch_lr.py](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/src/from_scratch_lr.py) · [metrics_scratch.py](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/src/metrics_scratch.py)
- **SQL and data pipelines.** Paged API ingestion of the aid data, cleaning rules that log every row and dollar removed, DuckDB models in numbered SQL files, and ten SQL checks that stop the run when one fails. For the scorecard, six Home Credit history tables rolled up to one row per applicant. [sql/](https://github.com/alvenyuka/kenya-aid-flows/tree/main/sql) · [checks/](https://github.com/alvenyuka/kenya-aid-flows/tree/main/checks) · [relational_features.py](https://github.com/alvenyuka/Credit-Risk-Scorecard/blob/main/src/relational_features.py)
- **Work someone else can re-run and monitor.** pytest on GitHub Actions in all five repos (on every push in four, in the monthly refresh for Kenya Aid Flows); the credit notebook imports tested code from `src/`, and Kiva's leakage guard is tested the same way; run records store the commit behind each result; a PSI drift check on later simulated fraud windows. [monitoring.py](https://github.com/alvenyuka/Fraud-Detection-System/blob/main/src/monitoring.py) · [MODEL_CARD.md](https://github.com/alvenyuka/Fraud-Detection-System/blob/main/MODEL_CARD.md)
